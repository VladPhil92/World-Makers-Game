# World Makers — First-Person Interaction Kit v1

## Status

This phase converts the approved first-person visual direction into a source-visible interaction layer that can be exercised before the final authored assets exist.

The implementation is **presentation-only**. Building, science, mission, interaction, movement and reward systems remain gameplay authority.

Current maturity: **source proxy ready**.

## What is now implemented

### 1. First-person camera presentation

`UWMPresentationSubsystem` can temporarily or persistently switch the existing player camera into a first-person interaction framing.

The override:

- converges the spring arm to zero length;
- moves the camera target toward child eye height;
- uses the mode-specific FOV from `FWMReferenceVisualPolishRuntime`;
- restores the normal third-person presentation when the interaction ends;
- preserves the existing third-person camera profile and cinematic/VFX presentation contracts.

The first-person path is not a new movement system and does not change pawn physics.

### 2. Source proxy viewmodel

`UWMFirstPersonInteractionComponent` creates a source proxy viewmodel for the local player:

- left hand proxy;
- right hand proxy;
- contextual tool proxy;
- wrist-device proxy;
- camera-attached viewmodel root.

The proxies use engine basic shapes only so the behavior remains visible and testable without falsely claiming production art exists.

Proxy properties:

- owner-only visibility;
- no collision;
- no navigation influence;
- no cast shadow;
- avatar body hidden only for the owning player while the first-person interaction is active.

This source proxy must later be replaced by the authored asset slots defined in the manifest.

## Interaction modes

The kit uses the five visual modes established in the reference-driven visual policy:

- `firstperson.explore`
- `firstperson.build`
- `firstperson.scan`
- `firstperson.measure`
- `firstperson.observe`

Build, scan and measure modes expose a tool. Observe intentionally minimizes the tool footprint. Explore remains the neutral presentation state.

## Semantic events

The kit does not invent a parallel gameplay state machine. It listens to semantic presentation events already emitted by World Makers.

Current routing:

- `gameplay.build.*` → `build-confirm`
- `science.*` → `scan-hold`
- `mission.measure.reveal` → `measure-focus`
- `world.observe.reveal` → `observe-focus`

`UWMPresentationSubsystem` discovers or creates the local `UWMFirstPersonInteractionComponent` and forwards those semantic events into the viewmodel.

This keeps the dependency direction correct:

**gameplay outcome → semantic event → presentation response**

not:

**presentation animation → gameplay success**.

## Interaction animation runtime

`FWMFirstPersonInteractionRuntime` provides a deterministic presentation state machine with the approved first-person action vocabulary:

1. `tool-raise`
2. `tool-lower`
3. `scan-anticipate`
4. `scan-hold`
5. `scan-settle`
6. `build-point`
7. `build-confirm`
8. `measure-focus`
9. `observe-focus`

The source runtime produces bounded transforms for:

- tool translation;
- tool rotation;
- left-hand translation;
- right-hand translation;
- tool scale;
- contextual HUD alpha;
- viewmodel bob;
- action envelope.

The current source proxy approximates anticipation, hold/contact and settle. Production animation clips may later replace these procedural transforms while keeping the same stable action IDs.

## Contextual HUD

`UWMFirstPersonContextWidget` is a real UMG widget generated by source code rather than a screenshot or mock.

It displays one compact contextual card with:

- mode label;
- short action guidance;
- domain-appropriate accent;
- bounded entrance/exit motion.

It follows the reference policy that only one contextual panel should be active at a time and does not normalize the high-density concept-art HUD as the runtime baseline.

## Reduced Motion

Reduced Motion remains an information-preserving mode.

When enabled:

- first-person camera/tool lag is removed by the visual profile;
- viewmodel bob becomes `0`;
- procedural pose amplitude is strongly reduced;
- HUD information remains visible;
- semantic meaning and interaction outcome do not change.

## Authored assets handoff

The canonical manifest is:

`content/visual/first-person/first-person-interaction-kit-v1.json`

The staged runtime copy is:

`game/Content/WorldMakers/Visual/first-person-interaction-kit-v1.json`

Required final authored assets are explicitly reserved at these stable slots:

- `/Game/WorldMakers/Characters/FirstPerson/SK_WM_FirstPersonArms`
- `/Game/WorldMakers/Tools/Scanner/SM_WM_Scanner`
- `/Game/WorldMakers/Tools/Build/SM_WM_BuildTool`
- `/Game/WorldMakers/Tools/Measure/SM_WM_MeasureTool`
- `/Game/WorldMakers/Tools/Wrist/SM_WM_WristDevice`

The nine production animation slots are also reserved under `/Game/WorldMakers/Animations/FirstPerson/`.

The manifest deliberately reports `authoredAssetsPresent: false`. Source proxy geometry is not evidence that those authored binaries exist.

## Certification boundary

This phase can certify source contracts, deterministic animation logic, semantic routing, contextual HUD structure and Reduced Motion safeguards in repository CI.

It cannot certify:

- final skeletal first-person arms;
- final scanner/build/measure/wrist models;
- final animation clips;
- skinning/deformation quality;
- animation blueprint integration;
- camera comfort on hardware;
- final tool screen occupancy;
- performance on representative tablets.

Those require **native Unreal** execution and **representative tablet** evidence.
